# 9P on this workstation

9P is the Plan 9 protocol WSL2 uses to cross the VM boundary. It is not a disk, not Git, and not a reason to copy trees. Source sync is **`git fetch` over SSH/HTTPS**. Compile, build, and run stay on one OS's native filesystem.

Official: [Working across file systems](https://learn.microsoft.com/en-us/windows/wsl/filesystems), [WSL interop](https://learn.microsoft.com/en-us/windows/dev-environment/wsl-interop), [`wsl.conf` automount](https://learn.microsoft.com/en-us/windows/wsl/wsl-config#automount-settings).

## Two directions

| Name | Path | Who is the client | This machine |
|---|---|---|---|
| Forward (drvfs) | `/mnt/c` `/mnt/d` `/mnt/o` `/mnt/p` | Linux reads Windows NTFS | **Off** on FedoraLinux-43 (`automount.enabled=false`, `mountFsTab=false`) |
| Reverse | `\\wsl$\FedoraLinux-43\...` `\\wsl.localhost\...` | Windows reads Linux ext4 | Exists whenever the distro is running. Not a workspace. |
| GPU drivers | `/usr/lib/wsl/drivers` | WSL internal | Harmless 9P. Ignore in preflight. |

`mount -t drvfs` still shows `type 9p` on WSL2. The fstype name `drvfs` is the Windows-side server.

Empty directories `/mnt/c` `/mnt/d` `/mnt/o` `/mnt/p` can exist after automount is disabled. They are **not** mounts. `findmnt /mnt/d` may print `/` because that path lives on ext4. Trust `findmnt -t 9p` and look for `aname=drvfs`.

## Fetch, not copy

Rule (user, 2026-10-18): no file moves between Windows and WSL2 in either direction. Each side gets source, scripts and this skill from GitHub on its own.

| Allowed | Why |
|---|---|
| `git fetch` / `git push` / `git clone` to GitHub, from each side's own repo | TCP; objects land on that side's own filesystem |
| A command line passed as wsl.exe argv (`--exec bash -lc '...'`, or base64 text decoded inside Linux, as `scripts/bg.sh` does) | It is a command, not a file |
| Reading a job's stdout, or `tail` of its log on its own side | Observation only; nothing is stored on the other side |

| Forbidden | Path | What happens |
|---|---|---|
| `cp` `rsync` `tar -C /mnt/...` `robocopy` into Linux | forward 9P | Slow metadata storm; GM7 if the Windows side is C:/D: |
| Explorer / `Copy-Item` to `\\wsl$\...` | reverse 9P | Same storm from the other side |
| `wslpath` then compile there | forward 9P | `/mnt/o/...` is still 9P even though O: is Optane |
| Cloning into `/mnt/d` then `git fetch` there | forward 9P | Fetch payload is fine; the repo metadata is 9P |
| Piping a file or script into wsl.exe stdin (`Get-Content job.sh \| wsl ...`, `fed.sh run/put`, `git bundle` over stdin) | pipe | A file crossed the boundary; the old `fed.sh` flow and `prune-linux-src.ps1` did this and are gone |
| Copying an SSH key into `~/.ssh` from Windows | any | Both sides share one secret; generate a key inside each side instead |

Co-location on Optane does not cancel 9P. `/mnt/p` is still a protocol hop into the VHDX file, not ext4.

## Do not automount drive letters

FedoraLinux-43 `/etc/wsl.conf` (do not flip these):

```ini
[automount]
enabled=false
mountFsTab=false
[interop]
appendWindowsPath=false
```

After a change: `wsl --terminate FedoraLinux-43`.

Do not:

- `sudo mount -t drvfs D: /mnt/d` (or O:/P:/C:)
- put `D: /mnt/d drvfs` in `/etc/fstab`
- start **fedoraremix** (no `wsl.conf`; it automounts every letter including O: and P:)
- set `WSLENV=.../p` so Windows `O:\WinCache` becomes `/mnt/o/WinCache`

`appendWindowsPath=false` keeps `git.exe` / `cargo.exe` off Linux `$PATH`. Those binaries would open `/mnt/c/Program Files/...` (9P) or confuse two Gits.

Admin vs non-admin shells can remount letters even when automount is false (microsoft/WSL#12443, fixed in some WSL builds). If `aname=drvfs` reappears, `umount` it and terminate the distro. Do not leave it.

## Compile

Microsoft: Linux tools on `/mnt/...` are the common performance mistake. Community measurements: `go build` ~4×, `git status` 10–20×, walks of thousands of files dominated by 9P `stat` (no cache, `msize=65536`).

| Pitfall | Why | What to do |
|---|---|---|
| `cargo build` / `rustc` on `/mnt` | per-crate `stat`/`open`/`unlink` round-trips | worktree on `$HOME` ext4; `target/` inside that tree |
| `go test` / compile on `/mnt` | module walk + build ID | `GOCACHE`/`GOMODCACHE` on ext4 (already in `~/.serein-env`) |
| `git status` / `worktree` on `/mnt` | every index entry is a 9P stat | `git -C "$HOME/repo.git"` |
| `chmod +x` / `chown` on `/mnt` | DrvFS without `metadata` maps to NTFS attributes, not Unix mode | never store `.ssh` or ELF on 9P |
| case folding | NTFS case-insensitive vs ext4 | `Foo.rs` / `foo.rs` collide on `/mnt` |
| CRLF | Windows checkouts on 9P | keep Linux trees in the Linux git |

Windows compile stays on NTFS (cache parent on O:). Do not aim `cargo.exe` at `\\wsl$\FedoraLinux-43\home\SR\...`.

## Build (link, incremental, caches)

| Pitfall | Why | What to do |
|---|---|---|
| Incremental `rustc` on reverse 9P | file locks (`LockFileEx`) missing on `\\wsl$` (microsoft/WSL#5762); rustc ICE; Cargo learned to ignore lock errors (rust-lang/cargo#7602) | Windows cargo on O: NTFS; Linux cargo on ext4 |
| Go module download via `\\wsl$` | Go does not treat WSL UNC as a supported FS (golang/go#37461) | `go` inside the distro |
| SQLite WAL / `*.lock` | 9P locking is not POSIX | git, cargo, go, and test DBs on the same OS as the process |
| `CARGO_HOME` / `GOCACHE` exported with `WSLENV /p` | path becomes `/mnt/o/...` | never export those vars into WSL |
| Mixing `git.exe` and `git` on one tree | two index writers, 9P plus NTFS | one Git per tree, native to that OS |

Copying a filled cache across 9P is both a 9P write storm and a wrong-path cache. Cold start on the cache parent.

## Run

| Pitfall | Why | What to do |
|---|---|---|
| `cwd` is `/mnt/...` when starting a Linux binary | all runtime `open`/`rename` pay 9P | `cd` to the worktree on `$HOME` first |
| `wsl.exe` from a Windows cwd on D: or O: | default Linux cwd follows the Windows cwd → `/mnt/d` if automount were on; with automount off the cwd can fail or land on an empty dir | always `wsl.exe -d FedoraLinux-43 -u SR --cd ~ --exec bash -lc 'cd ~/src/... && ...'` |
| Background process inside WSL | the distro stops about a minute after the last wsl.exe exits and kills it; `/tmp` (tmpfs) goes with it | `scripts/bg.sh linux ...` keeps a hidden wsl.exe alive for the job; logs in `~/logs` |
| inotify / `cargo watch` / rust-analyzer on `/mnt` | inotify is not plumbed through 9P | watchers only on ext4 |
| Unix sockets, pipes, flock | not a Windows file | stay on ext4 |
| Execute Linux ELF from Explorer `\\wsl$\...` | Windows cannot exec ELF | `wsl.exe -d FedoraLinux-43 -u SR --cd ~ --exec /home/SR/<path>` |
| Execute Windows `.exe` from Linux with `appendWindowsPath` | pulls Win32 tools; their file IO is NTFS but args may be `/mnt` paths | keep interop PATH off; use `wsl.exe` from Windows |
| Product TUN/CLI tests | those are Win32; their state is on Windows | run on O: NTFS, not `\\wsl$` |

## Preflight

`scripts/wt.sh check` on each side (SKILL.md section 9). On Linux it checks automount and Windows PATH are off in `/etc/wsl.conf`, no `aname=drvfs` 9P mount exists, and GOCACHE is under `$HOME`. `findmnt -t 9p` still lists `/usr/lib/wsl/drivers` (aname=drivers); that line is expected.
